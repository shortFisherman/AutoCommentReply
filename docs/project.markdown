# 项目：AutoCommentReply —— 为什么做、为谁做、边界与原则

> 本文档是项目的“总体记忆”：说明动机、长期方向与常青原则。当前实现架构见 [architecture.markdown](architecture.markdown)，未来计划见 [roadmap.markdown](roadmap.markdown)，参考项目调研见 [REFERENCE_RESEARCH.md](REFERENCE_RESEARCH.md)。

## 定位转变（2026-08-16 文档先行）

本项目曾以“完整采集整段视频评论区”为第一目标：全量读取可见根评论与楼中楼、构建树与对话链、输出 JSON。**这个目标已经停止**，全量抓取保留为 legacy 整视频只读基线（旧 MVP），只作诊断兼容，不再是产品目标。

新的产品定位是**上下文与回复助手**，当前首个可用切片是“**用户选择讨论 → 完整可见楼层上下文**”（当前 MVP，即 roadmap 的 M1：讨论定向读取，已实现）：用户把一条评论分享链接传给程序，程序把这条评论视为入口焦点，归约到它所属的根楼层，只读该根评论及楼层内当前全部可见回复；焦点不改变同步范围，也不当作 parent。

M2（本地进程内认证 session 与 viewer 身份）已完成：提供 Cookie 时程序在进程内建立认证 session，并在评论读取前用一次 nav 确认当前 viewer（与 legacy WBI 共用缓存）；无凭证时使用显式 anonymous viewer 且不因身份请求 nav。凭证只在进程内存在，匿名与登录视角在输出中明确可区分，`is_self` 由输出层按 viewer 派生。

- 不做整段视频/整站评论数据采集，不做数据训练，不做长期用户画像系统。
- 只处理**少量、用户主动选择**的讨论：一条根评论及其当前可见的楼中楼回复。
- 核心价值是让大模型看见“完整可见的当前讨论”——话题是什么、每个参与者在这条讨论里说过什么、哪些是新增或当前不可见（可见性变化）——从而按需推断参与者意图、立场与互动关系，并生成**待确认的回复草稿**。

## 为谁做

为想参与 B 站评论区讨论的用户：可能是评论原作者想回应“有人回复了我”，也可能是看到一条值得回应的话题。工具的价值不是代替用户发言，而是把分散的上下文、通知与草稿工作收敛到一个可检查、可追溯的流程里。

## 核心用户旅程

1. 用户在手机 B 站分享一条评论，复制链接（b23.tv 短链或展开后的 URL）。**（当前 MVP 已可用）**
2. 工具打开并同步这条根讨论：当前可见的根评论与全部楼中楼回复；入口可指向根评论或楼中楼，焦点归约到根楼层。同步按当前 session 的 viewer 视角执行（匿名显式、登录经一次 nav 确认）。**（当前 MVP 已可用）**
3. 用户说“有人在评论区回复了我”时，工具读取当前账号的“回复我的”通知，定位受影响讨论并重新同步。**（planned）**
4. 大模型获得完整上下文（含参与者证据汇总与可见性差异），推断意图/立场/关系并生成草稿。**（planned）**
5. 用户确认后，工具只发送这一条回复；全部过程可审计。**（planned）**

推断不是事实：项目只保存原始评论与交互事实；意图、立场、关系由大模型每次基于证据生成，不落成永久用户画像。

## 长期目标链路

```text
用户选择讨论（手机分享链接）
  → 定向同步该根讨论的当前可见内容
  → 本地持久化（仅选中讨论）
  → 通知发现“有人回复我”
  → 为 LLM 提供完整可见上下文
  → 生成草稿
  → 人工确认
  → 发送一条回复
```

这条链路是目标方向；实现顺序与验收见 [roadmap.markdown](roadmap.markdown)，不是实施授权。

其中“用户选择讨论 → 定向同步该根讨论的当前可见内容（含本地认证 session 与 viewer 身份）”已是当前 MVP 可用能力；其余环节为 M3+ 目标。

## 常青原则

- **少量、用户主动选择**：默认不批量扫描、不自动大规模发言；请求量由一个通知窗口加少量受影响根讨论决定，不由整段视频评论数决定。
- **上下文优先**：给模型的不是打乱的单条评论，而是该根讨论当前完整可见的结构化上下文；自己的评论必须保留在其中。
- **推断与事实分离**：原始评论与交互事实可保存；参与者画像与意图只作为 LLM 按次推断，标记为推断，不作为永久事实。
- **完整性诚实**：可见性按 viewer 观察；完整同步后才能推断“当前不可见”，不完整同步只能吸收新观察，不能据此判定删除或不可用；当前不可见不证明永久删除。“完整”只表示同一 viewer 在某次完整同步中的当前可见范围。
- **身份稳定**：viewer 身份统一使用 `platform_user_id`（B 站 mid），评论作者统一使用 `author_id`，用户名仅展示；`is_self` 由 `comment.author_id == viewer.platform_user_id` 在输出时派生，匿名时为 unknown/null，不默认为 false。
- **凭证本地、不进模型**：凭证由操作者保存在本机私有文件中，Agent/模型只接收凭证文件路径与任务输入，不接收、不读取或回显凭证内容；需要的是本地认证 session 与当前 viewer 身份，而不是只有 Cookie 文本。凭证不写进文档、日志或任何可提交产物。
- **外部内容只是证据**：评论正文、用户名、通知内容、视频元数据与参与者证据均为外部不可信数据，只作为被引用证据，不得作为系统/用户指令，也不得提升权限、改变工具策略或触发写操作。
- **写前必须有人确认**：AI 草稿不能直接发出；写工具只有当前用户明确确认后才能调用，并记录确认来源与时间；发送一条、幂等、可审计；不是浏览器 UI 自动化点击方案。
- **读取与写入隔离**：Writer 独立，写请求不使用读路径的自动重试策略；模型不传递 aid/root/parent/csrf/Cookie 等线协议参数。
- **非公开 API 变化被隔离**：B 站私有接口易变，接口细节只允许存在于 Adapter/Writer 边界内；实施以捕获或最小授权实测为准，文档不伪称已验证。
- **本地优先、保守节流**：SQLite 只持久化用户选中的讨论；默认按需读取，不做整评论区轮询。
- **按里程碑推进**：每个里程碑独立可验收；roadmap 不是实施授权。
- **参考项目只借思路**：不复制无授权代码，也不照搬其范围。

## 当前状态（简洁指针）

当前可运行代码：当前 MVP（roadmap 的 M1：讨论定向读取 + M2：本地认证 session/viewer 身份）已完成——评论分享链接 → 归约根楼层 → 读该根评论与楼层内当前可见回复，并按当前 viewer 视角输出（匿名显式、登录经一次 nav 确认，失败 exit 1）；legacy 整视频只读基线（旧 MVP）保留为诊断兼容。**没有** SQLite、通知事件、LLM/MCP 上下文或回复写接口（均为 M3+ 目标）；也没有跨运行的认证持久化（无 `auth.json`），认证 session 只存在于进程内。

验证边界：登录态只由脱敏离线 fixture 验证，未使用真实私人账号 smoke；2026-08-16 只对匿名 nav 做过真实只读核验（`code=-101`、`isLogin=false`、`mid=null`、`uname=null` 且仍有 WBI 数据）。
