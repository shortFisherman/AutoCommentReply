## Risks and skipped work

- M3 persistence is verified only by offline automated tests (MockTransport + temp SQLite); no real private account or real network --database smoke was performed. This is a documented, spec-consistent known limit, not an acceptance failure.
- SQLite and JSON stdout/file are not one cross-media atomic transaction: if JSON publication fails after DB commit, the committed ledger remains and the CLI exits 1; convergence relies on the tested idempotent rerun semantics. Documented known limit.
- A63 has no automated multi-writer differing-snapshot race test; correctness rests on BEGIN IMMEDIATE writer serialization verified by code inspection, while the only concurrency test covers simultaneous first-open schema creation.
- storage.py defines a transaction_start fault hook but tests only exercise before_commit; docs/architecture.markdown phrases fault coverage as transaction_start/before_commit, which slightly overstates the tested points (mechanism exists and A2/A64 are still substantively covered).
